## Phase 1: what exists

- **Project:** Expo SDK 57, RN 0.86, React 19.2 with the React Compiler, TypeScript 6 strict, Expo Router with routes in `src/app`. Every native library in the spec is already installed, so later phases rarely need a new dev-client build.
- **Theme:** `src/theme/tokens.ts` feeds both Tailwind (`tailwind.config.ts`) and `ThemeProvider` (CSS variables via NativeWind `vars()`). System, light and dark modes, with the choice persisted through the expo-sqlite kv-store (synchronous, so there's no flash on launch). Native chrome follows via `Appearance.setColorScheme`. A Reduce Motion override sits on top of the OS setting.
- **Fonts:** Fraunces 500 (plus italic and 600) and DM Sans 400–700, loaded per weight behind the splash screen.
- **Primitives:** AnimatedPressable, Text, Button, IconButton, Chip, Card, Sheet, Swatch, Skeleton, EmptyState, Segmented, Toggle, Screen, SectionHeader. All of them are on show at Me → Design system.
- **Navigation:** custom floating tab bar (Today · Wardrobe · + · Planner · Me) with a raised accent "+" that opens `/add` as a full-screen modal. Screens pad for it with `useTabBarInset()`.
- **Database:** Drizzle schema for all 11 spec tables, plus `latitude`/`longitude` on trips, `quantity` on trip items, `locked` on outfit items, and `archivedNote`, `category` and `colors` on wishlist. Every table has a UUID primary key, createdAt/updatedAt and a soft-delete `deletedAt`. Migrations are generated by drizzle-kit and applied on launch by `DatabaseGate`. Live queries are on (`enableChangeListener`).
- **Seed:** 36 garments (2 in Storage) plus 3 wishlist entries, with placeholder cutouts (WebP with alpha, 1200px plus a 400px thumb) rendered from the prototype silhouettes. About 8 months of generated wear history (roughly 220 logs) keeps wearCount, lastWornAt, cost-per-wear and the "forgotten" pieces consistent. Also 6 outfits, 4 planned days, a Lisbon trip with a packing list, and the statuses worn ×3, laundry ×3, lent ×2 (Nadia, Jo), dry cleaner ×1 and storage ×2.
- **Placeholder screens** read real data: Today shows status tiles, Wardrobe shows zones with thumbnails and empty hangers for pieces that are out, Planner shows upcoming plans, and Me has settings plus "Reset demo data" in a sheet.
- **Tests (59):** WCAG contrast for every text/background token pair in both themes, dates, colour helpers, and seed-plan consistency.

## Decisions

1. **Routes live in `src/app`.** That's the SDK 57 template default and what `AGENTS.md` expects. Everything else follows the spec's feature folders under `src/`.
2. **Contrast fixes.** Muted text is `#6E6860`, the spec's `#8A847C` is kept as `faint`, and filled accent buttons use `#C2412C`. Details are in DESIGN.md.
3. **Styling.** NativeWind 4.2 with Tailwind 3.4. NativeWind 5 is still a release candidate.
4. **Theming through CSS variables** set by ThemeProvider, so no `dark:` variants are needed anywhere.
5. **Seed cutouts** are WebP with alpha (about 25KB each, against about 800KB as PNG). The silhouette shadow is drawn at runtime from the alpha mask.
6. **Demo data loads automatically on first launch** until onboarding exists. Onboarding will then offer "Load demo wardrobe" or "Start empty".
7. **Day keys:** wear logs and plans store the local calendar day as `"YYYY-MM-DD"` text to avoid timezone drift.
8. **Join tables also get UUIDs and timestamps** (for sync tombstones), with unique indexes on their natural keys.
9. **Tab bar blur:** iOS uses expo-blur. Android uses an opaque glass fill, because Android blur needs a `BlurTargetView` around the content.
10. **Preferences** (theme, units, currency, reduce motion) live in a persisted Zustand store backed by `expo-sqlite/kv-store`. No AsyncStorage dependency.
11. **Added `expo-blur`.** It isn't in the spec's stack list; it's used for the frosted tab bar.

## Open questions

1. **Wardrobe direction:** A (stacked zones, the spec default), B (elevation, tap to zoom) or C (editorial spreads)? Phase 2 builds A unless told otherwise.
2. **Onboarding** isn't in any phase of the spec. Proposal: build it in phase 3 (alongside the camera permission flow) or phase 8.
3. **Bundle identifier** is `com.mycloset.app`. Change it in `app.json` before building to a physical device or the stores.
4. **Real garment photos:** the owner plans to upload cutouts and photos. They can replace the placeholders in `assets/seed/` (keep the slugs, run `npm run assets` only for regenerated placeholders), or be added through the phase 3 flow.
5. **Background removal library (phase 3):** pick a maintained Expo module or community library for iOS Vision and ML Kit Subject Segmentation once phase 3 starts, and verify it against SDK 57.
